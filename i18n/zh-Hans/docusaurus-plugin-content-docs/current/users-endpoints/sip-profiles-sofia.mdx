# 第 7 章：使用 Sofia 的 SIP 配置实例 {#chapter-7-sip-profiles-with-sofia}

`mod_sofia` 是 FreeSWITCH 基于 Sofia-SIP 协议栈构建的 SIP 端点模块。SIP 配置实例（Profile）定义一个绑定到指定 IP 地址和端口的独立 SIP 用户代理；FreeSWITCH 中每个 SIP 用户代理都是独立的配置实例，有自己的传输方式、编解码器偏好、认证策略和拨号计划路由目标。

<SignalWireCallout
  title="无需编写配置实例 XML 的 SIP 服务"
  href="https://signalwire.com/docs/platform/voice/sip/bring-your-own-carrier"
  page="sip-profiles"
  linkText="查看托管 SIP 和自带运营商（BYOC）">

在托管式 SignalWire 平台上，SIP 端点、域名和运营商对接都是通过 API 或控制台创建的资源。注册、NAT 处理和 TLS 由平台负责，同时仍支持接入自己的运营商。

</SignalWireCallout>

## Sofia 配置实例模型 {#the-sofia-profile-model}

每个 Sofia SIP 配置实例只服务一个 IP 地址与端口组合。通过运行多个配置实例，FreeSWITCH 可以在同一主机上提供彼此分离的 SIP 用户代理，例如一个用于内部已注册话机，另一个用于出站运营商中继。配置实例互相独立：每个都有自己的传输套接字、[ACL 规则](../integration/access-control-lists.mdx)、[编解码器偏好](../media/codecs-and-negotiation.mdx)、认证要求及拨号计划上下文。

所有配置实例 XML 文件都位于 `conf/sip_profiles/`。模块级配置文件 `conf/autoload_configs/sofia.conf.xml` 使用 `X-PRE-PROCESS` include 指令加载该目录下所有 `*.xml` 文件：

```xml
<profiles>
  <X-PRE-PROCESS cmd="include" data="../sip_profiles/*.xml"/>
</profiles>
```

要增加一个配置实例，请将新 XML 文件放进 `conf/sip_profiles/`，在 FreeSWITCH 控制台运行 `sofia profile <name> start`，或者重启模块。

## Sofia 全局设置 {#global-sofia-settings}

`sofia.conf.xml` 还包含一个应用于所有配置实例的 `global_settings` 块。

```xml
<global_settings>
  <param name="log-level" value="0"/>
  <param name="debug-presence" value="0"/>
  <!-- <param name="auto-restart" value="false"/> -->
  <!-- <param name="abort-on-empty-external-ip" value="true"/> -->
  <!-- <param name="capture-server" value="udp:homer.domain.com:5060"/> -->
</global_settings>
```

| 参数 | 用途 | 可用值 | 默认值 |
|---|---|---|---|
| `log-level` | Sofia-SIP 协议栈日志详细程度 | `0`–`9` | `0` |
| `debug-presence` | 呈现状态子系统调试日志详细程度 | `0`–`9` | `0` |
| `auto-restart` | 配置变更后自动重新加载配置实例 | `true`、`false` | `true` |
| `abort-on-empty-external-ip` | `ext-rtp-ip` 或 `ext-sip-ip` 解析为空时中止加载配置实例 | `true`、`false` | `false` |
| `capture-server` | 用于镜像 SIP 消息的 HEP 抓包服务器 | `udp:host:port` 或 `udp:host:port;hep=3;capture_id=N` | 无 |

## 配置实例文件结构 {#profile-file-structure}

配置实例 XML 文件具有如下基本结构：

```xml
<profile name="internal">
  <aliases>
    <!-- <alias name="default"/> -->
  </aliases>

  <gateways>
    <!-- outbound provider registrations -->
  </gateways>

  <domains>
    <domain name="all" alias="true" parse="false"/>
  </domains>

  <settings>
    <param name="sip-port" value="5060"/>
    <!-- ... additional parameters ... -->
  </settings>
</profile>
```

### `gateways` 块 {#the-gateways-block}

向上游运营商或 SIP 中继发起的出站 SIP 注册定义在 `<gateways>` 中。`external` 配置实例通过 include 加载各个网关文件：

```xml
<gateways>
  <X-PRE-PROCESS cmd="include" data="external/*.xml"/>
</gateways>
```

每个网关 XML 文件定义一个出站注册。有关网关的说明参见[第 8 章：网关与中继注册](../users-endpoints/gateways.mdx)。

### `aliases` 块 {#the-aliases-block}

别名是配置实例在拨号计划字符串及 API 调用中可使用的替代名称。每个配置实例可以拥有多个别名。

```xml
<aliases>
  <alias name="default"/>
  <alias name="outbound"/>
</aliases>
```

别名让 `sofia/default/1000@domain.com` 这样的拨号计划桥接字符串能够解析到 `internal` 配置实例，即使实例本身的名称是 `internal`。

### `domains` 块 {#the-domains-block}

`domains` 块控制两种相互独立的行为：配置实例是否解析用户目录中的域级网关定义，以及是否把列出的各域名用作该实例的路由别名。

```xml
<domains>
  <domain name="all" alias="true" parse="false"/>
</domains>
```

| 属性 | 用途 | 可用值 |
|---|---|---|
| `name` | 要作用的域名，或使用特殊值 `all` 匹配全部已配置域名 | FQDN 或 `all` |
| `alias` | 将此域名别名映射到配置实例，使发往该域名的 SIP URI 在此解析 | `true`、`false` |
| `parse` | 解析该域名的 FreeSWITCH 用户目录并加载其中定义的全部网关 | `true`、`false` |

设置 `alias="true"` 且 `name="all"`，会使目录中的每个域名都成为该配置实例的别名。这是 `internal` 配置实例的默认值，支持已注册端点的多域名路由。

设置 `parse="true"` 会指示配置实例读取指定域名的 XML 用户目录，并加载其中找到的 `<gateway>` 配置段。`external` 配置实例默认使用 `parse="true"` 和 `alias="false"`，因此会加载目录中的网关，但不会把所有域名的 SIP URI 路由到自己。

### `settings` 块 {#the-settings-block}

每个配置实例的运行参数都以 `<settings>` 内的 `<param name="..." value="..."/>` 元素声明。完整参考见第 5 节。

## 随附的配置实例 {#bundled-profiles}

默认配置提供两个实例：`internal` 和 `external`。它们覆盖两类主要使用场景，并作为自定义实例的模板。

### `internal` 配置实例 {#the-internal-profile}

**文件：** `conf/sip_profiles/internal.xml`

`internal` 配置实例面向桌面电话、软电话及 WebRTC 客户端等需要注册的 SIP 端点。它监听端口 `5060`（变量 `$${internal_sip_port}`），并默认强制摘要认证（`auth-calls` 经 `$${internal_auth_calls}` 解析为 `true`）。

默认 `internal` 配置实例的主要特点：

- 将 `sip-ip` 和 `rtp-ip` 绑定到 `$${local_ip_v4}`（系统检测到的本地 IPv4 地址）。
- 将入站呼叫路由到 `public` 上下文。
- 使用 `domains` ACL 对入站呼叫授权（`apply-inbound-acl` = `domains`）。
- 启用呈现状态（`manage-presence` = `true`）。
- 为 WebRTC 客户端启用 WebSocket（`ws-binding` = `:5066`）和安全 WebSocket（`wss-binding` = `:7443`）。
- 通过 `force-register-domain` 将所有注册强制归入 `$${domain}` 定义的单一域名。
- 将 `challenge-realm` 设为 `auto_from`，即摘要认证挑战中的 SIP realm 取自 `From` 头。
- 启用 `inbound-late-negotiation`，使拨号计划可以选择编解码器。

```xml
<profile name="internal">
  <aliases></aliases>
  <gateways></gateways>
  <domains>
    <domain name="all" alias="true" parse="false"/>
  </domains>
  <settings>
    <param name="context" value="public"/>
    <param name="sip-port" value="$${internal_sip_port}"/>
    <param name="sip-ip" value="$${local_ip_v4}"/>
    <param name="rtp-ip" value="$${local_ip_v4}"/>
    <param name="ext-rtp-ip" value="$${external_rtp_ip}"/>
    <param name="ext-sip-ip" value="$${external_sip_ip}"/>
    <param name="dialplan" value="XML"/>
    <param name="auth-calls" value="$${internal_auth_calls}"/>
    <param name="inbound-codec-prefs" value="$${global_codec_prefs}"/>
    <param name="outbound-codec-prefs" value="$${global_codec_prefs}"/>
    <param name="inbound-codec-negotiation" value="generous"/>
    <param name="inbound-late-negotiation" value="true"/>
    <param name="manage-presence" value="true"/>
    <param name="presence-hosts" value="$${domain},$${local_ip_v4}"/>
    <param name="apply-inbound-acl" value="domains"/>
    <param name="apply-nat-acl" value="nat.auto"/>
    <param name="nonce-ttl" value="60"/>
    <param name="auth-calls" value="$${internal_auth_calls}"/>
    <param name="auth-all-packets" value="false"/>
    <param name="auth-subscriptions" value="true"/>
    <param name="inbound-reg-force-matching-username" value="true"/>
    <param name="challenge-realm" value="auto_from"/>
    <param name="rtp-timeout-sec" value="300"/>
    <param name="rtp-hold-timeout-sec" value="1800"/>
    <param name="hold-music" value="$${hold_music}"/>
    <param name="record-path" value="$${recordings_dir}"/>
    <param name="record-template" value="${caller_id_number}.${target_domain}.${strftime(%Y-%m-%d-%H-%M-%S)}.wav"/>
    <param name="tls" value="$${internal_ssl_enable}"/>
    <param name="tls-bind-params" value="transport=tls"/>
    <param name="tls-sip-port" value="$${internal_tls_port}"/>
    <param name="tls-version" value="$${sip_tls_version}"/>
    <param name="ws-binding"  value=":5066"/>
    <param name="wss-binding" value=":7443"/>
    <param name="force-register-domain" value="$${domain}"/>
    <param name="force-subscription-domain" value="$${domain}"/>
    <param name="force-register-db-domain" value="$${domain}"/>
  </settings>
</profile>
```

### `external` 配置实例 {#the-external-profile}

**文件：** `conf/sip_profiles/external.xml`

`external` 配置实例用于向 SIP 运营商及上游中继发起出站注册。它监听端口 `5080`（变量 `$${external_sip_port}`），并禁用入站呼叫认证（`auth-calls` = `false`），因为运营商并非以用户身份注册，而是在网络或 IP 层进行认证。

默认 `external` 配置实例的主要特点：

- 监听端口 `5080`。
- 将 `auth-calls` 设为 `false`；通常按 IP 信任运营商流量。
- 将 `manage-presence` 设为 `false`；中继流量无需呈现状态。
- 通过 `gateways` include 从 `conf/sip_profiles/external/*.xml` 加载网关定义。
- 在 `domains` 块中使用 `parse="true"` 加载用户目录中定义的网关；使用 `alias="false"` 避免将域名的 SIP URI 自动路由到此实例。

```xml
<profile name="external">
  <gateways>
    <X-PRE-PROCESS cmd="include" data="external/*.xml"/>
  </gateways>
  <aliases></aliases>
  <domains>
    <domain name="all" alias="false" parse="true"/>
  </domains>
  <settings>
    <param name="context" value="public"/>
    <param name="sip-port" value="$${external_sip_port}"/>
    <param name="sip-ip" value="$${local_ip_v4}"/>
    <param name="rtp-ip" value="$${local_ip_v4}"/>
    <param name="ext-rtp-ip" value="$${external_rtp_ip}"/>
    <param name="ext-sip-ip" value="$${external_sip_ip}"/>
    <param name="dialplan" value="XML"/>
    <param name="auth-calls" value="false"/>
    <param name="inbound-codec-prefs" value="$${global_codec_prefs}"/>
    <param name="outbound-codec-prefs" value="$${outbound_codec_prefs}"/>
    <param name="inbound-codec-negotiation" value="generous"/>
    <param name="inbound-late-negotiation" value="true"/>
    <param name="manage-presence" value="false"/>
    <param name="nonce-ttl" value="60"/>
    <param name="rtp-timeout-sec" value="300"/>
    <param name="rtp-hold-timeout-sec" value="1800"/>
    <param name="hold-music" value="$${hold_music}"/>
    <param name="tls" value="$${external_ssl_enable}"/>
    <param name="tls-bind-params" value="transport=tls"/>
    <param name="tls-sip-port" value="$${external_tls_port}"/>
    <param name="tls-version" value="$${sip_tls_version}"/>
  </settings>
</profile>
```

## 设置参数参考 {#settings-parameter-reference}

### 身份与监听绑定 {#identity-and-binding}

以下参数定义配置实例绑定的地址和端口，以及如何分派入站呼叫。

| 参数 | 用途 | 可用值 | 默认值 |
|---|---|---|---|
| `sip-ip` | SIP 传输套接字的本地 IP 地址。只能使用 IP 地址，不能使用主机名。支持 `auto`（系统推测的 IP）、`interface:NAME`（按网卡名称解析）或显式点分十进制地址。 | IP 地址、`auto`、`interface:[auto\|ipv4\|ipv6]/IFNAME` | 系统推测的本地 IPv4 |
| `sip-port` | SIP 传输监听的 UDP/TCP 端口。支持 `auto`，让操作系统分配端口。 | 端口号或 `auto` | `5060` |
| `rtp-ip` | SDP 中用作 RTP 源/目的的本地 IP 地址。接受与 `sip-ip` 相同的形式。支持多个 `rtp-ip` 条目，配置实例会为每个呼叫选择合适的地址。 | IP 地址、`auto`、`interface:[auto\|ipv4\|ipv6]/IFNAME` | 系统推测的本地 IPv4 |
| `context` | 入站呼叫交付到的拨号计划上下文。可由每呼叫 `user_context` 通道变量或 ACL 通过/失败上下文覆盖。 | 任意已定义拨号计划上下文名称 | `default` |
| `dialplan` | 处理入站呼叫的拨号计划模块。 | `XML`、`inline` 或任意已加载的拨号计划模块名 | `XML` |
| `bind-params` | 附加到 SIP 监听 URI 的传输参数，例如限制传输协议。 | 传输参数字符串，如 `transport=udp` | 无 |
| `user-agent-string` | 覆盖此配置实例发送的 SIP `User-Agent` 头。设为 `_undef_` 可完全省略该头。 | 任意字符串或 `_undef_` | `FreeSWITCH-mod_sofia/<version>` |
| `contact-user` | 此配置实例构造的 SIP Contact URI 中的用户部分。 | 字符串 | `mod_sofia` |
| `sip-domain` | 覆盖此配置实例报告的 SIP 域名。未设置时默认使用 `sip-ip`。 | FQDN 或 IP 地址 | `sip-ip` 的值 |
| `outbound-proxy` | 强制所有出站 SIP 请求通过此代理 URI；缺少 `sip:` scheme 时自动添加。 | SIP URI，如 `sip:proxy.example.com` | 无 |
| `max-calls` | 此配置实例允许的最大并发呼叫数。`0` 表示不限制。 | 整数 | `0` |

### 认证与注册 {#authentication-and-registration}

| 参数 | 用途 | 可用值 | 默认值 |
|---|---|---|---|
| `auth-calls` | 要求入站 INVITE 请求使用摘要认证。 | `true`、`false` | `false` |
| `auth-all-packets` | 启用认证时，对每种 SIP 请求方法都进行挑战，而不仅是 INVITE。 | `true`、`false` | `false` |
| `auth-messages` | 要求入站 MESSAGE 请求使用摘要认证。 | `true`、`false` | `true` |
| `auth-subscriptions` | 要求 SUBSCRIBE 请求使用摘要认证。 | `true`、`false` | `true` |
| `accept-blind-reg` | 接受任何 REGISTER 请求，不向用户目录验证凭据。仅适用于测试环境。 | `true`、`false` | `false` |
| `accept-blind-auth` | 接受任何摘要认证响应，不验证密码。仅适用于测试环境。 | `true`、`false` | `false` |
| `apply-inbound-acl` | 对入站呼叫来源 IP 应用的 ACL 名称。通过 ACL 的呼叫可通过 `acl-name:pass-context:fail-context` 语法交付到可选上下文。支持多个同名参数。使用 `none` 清除。 | ACL 名称、`none` 或 `acl:pass-ctx:fail-ctx` | 无 |
| `apply-register-acl` | 对 REGISTER 来源 IP 应用的 ACL 名称。IP 不在 ACL 中时拒绝注册。支持多个实例；使用 `none` 清除。 | ACL 名称或 `none` | 无 |
| `apply-proxy-acl` | 对经由代理到达的请求应用的 ACL 名称（根据 `Via` 头判断）。支持多个实例；使用 `none` 清除。 | ACL 名称或 `none` | 无 |
| `nonce-ttl` | 摘要认证 nonce 的有效期（秒）。启动时，小于 `60` 的值会强制调整为 `60`。 | 整数秒 | `60` |
| `max-auth-validity` | 允许重用 nonce 的最大次数，超过后需要新的挑战。`0` 表示在 `nonce-ttl` 内无限次重用。 | 整数 | `0` |
| `challenge-realm` | 摘要认证挑战中 `realm` 字段的值。`auto_from` 从 SIP `From` 头主机部分获取，`auto_to` 从 `To` 头获取，其他字符串按字面值使用。固定字符串会禁用多域名认证。 | `auto_from`、`auto_to` 或任意字面字符串 | `auto_to` |
| `inbound-reg-force-matching-username` | 如果 `Authorization` 头的 `username` 字段不等于 `From` URI 的用户部分，则拒绝注册。 | `true`、`false` | `false` |
| `multiple-registrations` | 允许同一用户同时从多个设备注册。`call-id` 以 Call-ID 跟踪注册，`contact` 按 Contact URI 跟踪。`true` 视为 `contact`。 | `false`、`call-id`、`contact`、`true` | `false` |

### 呈现状态与注册域名 {#presence-and-registration-domain}

| 参数 | 用途 | 可用值 | 默认值 |
|---|---|---|---|
| `manage-presence` | 启用配置实例的呈现状态引擎。`true` 启用完整状态服务；`passive` 采用只读/中继模式（用于共享 `internal` 的状态）；`pnp` 启用即插即用配置下发状态；`false` 禁用状态功能。 | `true`、`false`、`passive`、`pnp` | `false` |
| `presence-hosts` | 此配置实例负责状态服务的主机名或 IP 列表（逗号分隔），用于把状态订阅匹配到正确实例。 | 逗号分隔的主机列表 | 无 |
| `force-register-domain` | 覆盖所有入站注册存入用户目录时采用的域名。适用于单域服务器，避免因请求中的不同域名导致注册分散存储。 | 域名 | 无（使用请求中的域名） |
| `force-register-db-domain` | 覆盖存储注册时使用的数据库键域名。通常与 `force-register-domain` 设为相同值。 | 域名 | 无（使用请求中的域名） |
| `force-subscription-domain` | 覆盖路由 SUBSCRIBE 请求时使用的域名。 | 域名 | 无（使用请求中的域名） |
| `record-path` | 此配置实例发起的通话录音的默认存储目录。 | 绝对路径 | `$${recordings_dir}` 的值 |
| `record-template` | 自动录音的文件名模板。支持 FreeSWITCH 通道变量展开和 `${strftime(...)}`。 | 含变量引用的字符串 | 无 |

### 媒体 {#media}

| 参数 | 用途 | 可用值 | 默认值 |
|---|---|---|---|
| `inbound-codec-prefs` | SDP answer 中向入站主叫提供的按优先级排序的编解码器列表。 | 逗号分隔的编解码器名称，如 `OPUS,G722,PCMU,PCMA` | 无（使用全局编解码器列表） |
| `outbound-codec-prefs` | 出站呼叫 SDP offer 中提供的按优先级排序的编解码器列表。 | 逗号分隔的编解码器名称 | 无（使用全局编解码器列表） |
| `codec-prefs` | 用单个参数将 `inbound-codec-prefs` 和 `outbound-codec-prefs` 设置为相同值。 | 逗号分隔的编解码器名称 | 无 |
| `inbound-codec-negotiation` | 控制如何将实例的编解码器列表与远端 SDP offer 协调。`generous` 选择远端 offer 中第一个本实例也支持的编解码器；`greedy` 根据实例自己的优先级列表对远端 offer 重新排序；`scrooge` 类似 `greedy`，并且拒绝任何不在实例列表中的编解码器。 | `generous`、`greedy`、`scrooge` | `generous` |

## 入门：最简可用配置实例 {#getting-started-minimal-working-profile}

以下最简配置实例足以在一台处于 NAT 后的主机上接收 SIP 呼叫并进行认证。可根据部署需要加入上面参考表中的其他参数。

```xml
<profile name="myprofile">
  <aliases></aliases>
  <gateways></gateways>
  <domains>
    <domain name="all" alias="true" parse="false"/>
  </domains>

  <settings>
    <!-- Bind to the local LAN address -->
    <param name="sip-ip"  value="192.0.2.10"/>
    <param name="rtp-ip"  value="192.0.2.10"/>
    <param name="sip-port" value="5060"/>

    <!-- Advertise the public IP to remote parties (NAT scenario) -->
    <param name="ext-sip-ip"  value="203.0.113.1"/>
    <param name="ext-rtp-ip"  value="203.0.113.1"/>

    <!-- Dialplan dispatch -->
    <param name="context"  value="default"/>
    <param name="dialplan" value="XML"/>

    <!-- Authentication -->
    <param name="auth-calls"    value="true"/>
    <param name="nonce-ttl"     value="60"/>
    <param name="challenge-realm" value="auto_from"/>

    <!-- ACL -->
    <param name="apply-nat-acl"      value="nat.auto"/>
    <param name="apply-inbound-acl"  value="domains"/>

    <!-- Codec preferences -->
    <param name="inbound-codec-prefs"       value="OPUS,G722,PCMU,PCMA"/>
    <param name="outbound-codec-prefs"      value="OPUS,G722,PCMU,PCMA"/>
    <param name="inbound-codec-negotiation" value="generous"/>

    <!-- RTP timer -->
    <param name="rtp-timer-name" value="soft"/>

    <!-- DTMF -->
    <param name="dtmf-type" value="rfc2833"/>

    <!-- Hold music -->
    <param name="hold-music" value="local_stream://moh"/>
  </settings>
</profile>
```

在 `conf/sip_profiles/myprofile.xml` 创建此文件后，使用以下命令加载：

```
sofia profile myprofile start
```

使用以下命令验证它正在运行：

```
sofia status
```

运行状态中应该出现该配置实例绑定的 SIP URI 和传输协议。

## 呈现状态、BLF 与 MWI {#presence-blf-and-mwi}

呈现状态（Presence）、忙灯指示（BLF）和消息等待指示（MWI）都依赖 SIP SUBSCRIBE/NOTIFY 机制。话机发送针对某个事件包的 SUBSCRIBE，状态发生相关变化时 FreeSWITCH 就发送 NOTIFY。本节的配置实例参数决定 FreeSWITCH 是否接受这些订阅以及如何处理。

### 启用呈现状态 {#enabling-presence}

每个配置实例通过 `manage-presence` 参数控制呈现状态。设为 `true` 时，配置实例注册完整的状态引擎：接受 dialog（BLF）和 message-summary（MWI）事件包的 SUBSCRIBE，将订阅保存到 `sip_subscriptions` 数据库表，并在状态变化时发送 NOTIFY。

```xml
<param name="manage-presence" value="true"/>
```

将 `manage-presence` 设为 `passive`，可启用只读中继模式。被动配置实例接受主呈现状态实例生成的状态事件，并向自己的订阅者转发 NOTIFY。适用于第二个配置实例（例如 `external`）需要中继状态，却不独立驱动状态的情况。

将 `manage-presence` 设为 `false`，会完全禁用该实例的呈现状态。`external` 默认使用 `false`，因为运营商中继不进行用户注册或呈现状态订阅。

`presence-hosts` 参数是以逗号分隔的主机名或 IP 列表，表示此配置实例负责哪些域的呈现状态。FreeSWITCH 根据该列表把入站 SUBSCRIBE 的 Request-URI 主机与已知实例匹配，也用于查询 `sip_subscriptions` 表中的匹配订阅者。默认 `internal` 实例将其设置为主域名和本地 IP：

```xml
<param name="presence-hosts" value="$${domain},$${local_ip_v4}"/>
```

如果话机订阅 `sip:1001@pbx.example.com`，且 `pbx.example.com` 出现在 `presence-hosts` 中，则该配置实例负责提供订阅服务。

`presence-privacy` 参数用于隐藏呈现状态 NOTIFY 中的主叫身份信息。设为 `true` 时，`early`、`confirmed` 和 `hold` 状态的 NOTIFY 消息体状态行不会包含远端姓名或号码，只显示 `Ring`、`On The Phone` 或 `Hold` 等通用文字，从而限制 BLF 观察者可见的信息。

### BLF（忙灯指示） {#blf-busy-lamp-field}

BLF 通过 SIP `dialog` 事件包（RFC 4235）实现。具有 BLF 按键的话机会发送 SUBSCRIBE，请求监控指定分机：

```
SUBSCRIBE sip:1001@pbx.example.com SIP/2.0
Event: dialog
Accept: application/dialog-info+xml
```

当接收实例的 `manage-presence` 为 `true` 时，FreeSWITCH 接受 SUBSCRIBE，保存到 `sip_subscriptions`，并立即发送 NOTIFY，反映分机 `1001` 当前的呼叫状态。此后，只要该分机的对话状态变化，就会继续发送 NOTIFY：呼叫进入时为 early、应答后为 confirmed、结束后为 terminated。

监控话机上的 BLF 按键必须指向分机的呈现状态标识。默认的呈现状态标识（通道变量 `presence_id`）为 `user@domain`。如果配置实例设置了 `force-subscription-domain`，就使用该域名替代 SUBSCRIBE URI 中的域名，确保单域部署时能够正确解析订阅。

FreeSWITCH 从 `sip_dialogs` 表查找活动对话，并与 `sip_registrations` 关联，以确定订阅对象的当前状态。NOTIFY 消息体格式为 `application/dialog-info+xml`。

**共享线路外观（SLA）**

`manage-shared-appearance` 参数根据 BroadSoft SCA 规范启用共享线路外观（Shared Line Appearance）。设为 `true` 还会强制将 `manage-presence` 设为完整模式并启用多重注册（`PFLAG_MULTIREG`）。SLA 允许注册到同一分机的多部电话通过呈现状态协调呼叫状态，因而所有设备都能反映共享线路是否被占用、正在通话或处于保持状态。应在为共享线路端点服务的配置实例上设置：

```xml
<param name="manage-shared-appearance" value="true"/>
```

### MWI（消息等待指示） {#mwi-message-waiting-indication}

MWI 使用 SIP `message-summary` 事件包（RFC 3842）。话机会订阅自身地址对应的事件包：

```
SUBSCRIBE sip:1001@pbx.example.com SIP/2.0
Event: message-summary
Accept: application/simple-message-summary
```

FreeSWITCH 保存订阅，每当该语音信箱的状态变化时便发送 NOTIFY。NOTIFY 消息体使用 `application/simple-message-summary` 格式，例如：

```
Messages-Waiting: yes
Message-Account: sip:1001@pbx.example.com
Voice-Message: 3/1 (0/0)
```

**语音信箱如何驱动 MWI**

`mod_voicemail` 每当收到、读取或删除留言时，都会触发一次 `SWITCH_EVENT_MESSAGE_WAITING` 事件。事件携带 `MWI-Messages-Waiting`、`MWI-Message-Account` 和 `MWI-Voice-Message` 头。`mod_sofia` 监听此事件，并从 `sip_subscriptions` 查询 `sub_to_user` 和 `sub_to_host` 与留言账号匹配的订阅者，为每个匹配订阅发送 NOTIFY。

**用户目录中的 `mwi-account` 变量**

如果用户的语音信箱与 SIP 注册地址不同，可在目录用户条目中设置 `mwi-account` 变量。话机注册时，FreeSWITCH 将 `mwi-account` 的值作为 `mwi_user` 和 `mwi_host` 保存在 `sip_registrations` 中。对应账号的语音信箱事件到达时，FreeSWITCH 按 `mwi_user` 和 `mwi_host` 匹配，即使没有显式订阅也会向已注册 Contact 发送 NOTIFY。因此，以 `1001@pbx.example.com` 注册的话机可以收到其他地址语音信箱的 MWI。

```xml
<!-- In conf/directory/default/1001.xml -->
<user id="1001">
  <params>
    <param name="password" value="1234"/>
  </params>
  <variables>
    <variable name="mwi-account" value="1001@voicemail.example.com"/>
  </variables>
</user>
```

`mwi-account` 的值是 `user@host` 字符串。缺少主机部分时，FreeSWITCH 回退到注册主机名。

### presence\_map.conf.xml {#presence_mapconfxml}

`presence_map.conf.xml` 将分机正则表达式模式映射到呈现状态协议标识符。当配置实例参数 `presence-proto-lookup` 为 `true`，且收到的 SUBSCRIBE 所订阅分机无法从订阅本身确定协议时，将查询该文件。FreeSWITCH 调用 `switch_ivr_check_presence_mapping()` 打开配置，遍历域名/分机条目，返回 `regex` 与订阅分机名匹配的第一个 `proto`。

主要用途是根据正则表达式识别会议室分机，将其订阅路由到 `conf` 呈现状态协议，而不是默认端点的状态处理。

在配置实例中启用查询：

```xml
<param name="presence-proto-lookup" value="true"/>
```

文件路径为 `conf/autoload_configs/presence_map.conf.xml`，结构如下：

```xml
<configuration name="presence_map.conf" description="PRESENCE MAP">
  <domains>
    <domain name="pbx.example.com">
      <!-- Extensions matching 3xxx map to conference presence -->
      <exten regex="3\d+" proto="conf"/>
      <!-- Extensions matching 4xxx map to park presence -->
      <exten regex="4\d+" proto="park"/>
    </domain>
  </domains>
</configuration>
```

在 `domain` 元素上使用 `name="*"` 匹配全部域名。每个 `exten` 元素按文档顺序评估，首个匹配生效。如果没有匹配条目，FreeSWITCH 使用标准呈现状态处理。

### 呈现状态参数参考 {#presence-parameter-reference}

以下参数位于配置实例的 `settings` 块。第 5.3 节已介绍的参数在此再次列出，以完整呈现状态功能组。

| 参数 | 用途 | 可用值 | 默认值 |
|---|---|---|---|
| `manage-presence` | 在此配置实例上启用或禁用呈现状态引擎。`true` 启用完整的 SUBSCRIBE/NOTIFY；`passive` 从主实例中继状态；`pnp` 启用即插即用配置下发状态；`false` 禁用状态功能。 | `true`、`false`、`passive`、`pnp` | `false` |
| `presence-hosts` | 此实例负责状态订阅的主机名或 IP 列表，以逗号分隔；用于匹配 SUBSCRIBE Request-URI 主机以及查询 `sip_subscriptions`。 | 逗号分隔的主机列表 | 无 |
| `presence-privacy` | 为 `true` 时，在 BLF NOTIFY 中隐藏主叫身份；状态只显示 `Ring`、`On The Phone`、`Hold` 等通用文字，不包含远端号码或姓名。 | `true`、`false` | `false` |
| `presence-probe-on-register` | 每次 REGISTER 时对注册端点发送呈现状态探测，强制其重新发布当前状态。 | `true`、`false` | `false` |
| `send-presence-on-register` | 注册时向该用户的全部观察者推送呈现状态。`true` 或 `all` 每次 REGISTER 都推送，`first-only` 只在某 Contact 首次 REGISTER 时推送。 | `true`、`all`、`first-only`、`false` | `false` |
| `manage-shared-appearance` | 启用 BroadSoft 共享呼叫外观（SCA/SLA），用于管理共享线路。设为 `true` 时也启用完整状态服务与多重注册。 | `true`、`false` | `false` |
| `presence-proto-lookup` | 为 `true` 时，如果无法从 SUBSCRIBE 判断订阅分机使用的呈现状态协议，则查询 `presence_map.conf.xml`。 | `true`、`false` | `false` |
| `presence-hold-state` | 控制通话处于保持时 BLF NOTIFY 报告的对话状态。`confirmed` 将保持呼叫报告为 confirmed（活动）；`terminated` 报告为 terminated；默认在对话 XML 中保留原始保持状态。 | `confirmed`、`terminated` | 无 |
| `force-subscription-domain` | 覆盖 SUBSCRIBE 路由使用的域名，确保单域部署能正确解析订阅。 | 域名 | 无（使用请求中的域名） |
| `auth-subscriptions` | 要求 SUBSCRIBE 进行摘要认证。在为注册端点服务的实例上应设为 `true`，以阻止未经认证的状态订阅。 | `true`、`false` | `true` |
