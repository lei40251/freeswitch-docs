# 第 32 章：通道变量目录 {#chapter-32-channel-variables-catalog}

通道变量是 FreeSWITCH 在一条呼叫腿生命周期内维护的、按通道划分的具名字符串值。在拨号计划表达式和应用参数中，可以使用 `${variable_name}` 引用。变量可能在主叫认证时由用户目录设置，由 `set`、`export` 等拨号计划动作设置，由 `mod_sofia` 等端点模块设置，也可能由核心应用在运行期间设置。通过 `set` 设置的变量仅作用于当前呼叫腿；`export` 则会将变量进一步传播至后续 `bridge` 创建的任一 B 腿。

托管的 SignalWire 使用 SWML（一种基于 JSON/YAML 的呼叫控制标记语言）保存每次呼叫的状态：[`set`](https://signalwire.com/docs/swml/reference/calling/set?utm_source=freeswitch-docs&utm_medium=callout&utm_campaign=same-engine&utm_content=channel-variables) 与 [`unset`](https://signalwire.com/docs/swml/reference/calling/unset?utm_source=freeswitch-docs&utm_medium=callout&utm_campaign=same-engine&utm_content=channel-variables) 用于管理文档变量，提示及检测结果也以具名值返回。因此，需要处理的变量范围从数千个通道变量缩减为 SWML 文档中显式声明的变量。

## 呼叫控制与路由 {#call-control-and-routing}

这些变量控制 FreeSWITCH 在桥接前、桥接期间以及桥接结束后的行为。

| 变量 | 用途 |
|---|---|
| <a id="var-continue_on_fail"></a>`continue_on_fail` | 控制桥接失败后拨号计划是否继续执行。设为 `true` 时，不论失败原因均继续；设为以逗号分隔的 Q.850 原因名称（如 `USER_BUSY,NO_ANSWER`）或数字代码（如 `17,18`）时，仅遇到所列原因才继续。默认：`false`。 |
| <a id="var-hangup_after_bridge"></a>`hangup_after_bridge` | 为 `true` 时，B 腿一挂机就终止 A 腿；为 `false`（默认）时，桥接返回后继续执行拨号计划。其判断顺序位于 `park_after_bridge` 与 `transfer_after_bridge` 之后。 |
| <a id="var-park_after_bridge"></a>`park_after_bridge` | 为 `true` 时，桥接返回后驻留呼叫，而不是继续拨号计划。先于 `hangup_after_bridge` 判断。 |
| <a id="var-park_after_early_bridge"></a>`park_after_early_bridge` | 为 `true` 时，在 B 腿应答前，早期媒体桥接一结束就驻留呼叫。对应 `switch_types.h` 中的 `SWITCH_PARK_AFTER_EARLY_BRIDGE_VARIABLE`。 |
| <a id="var-transfer_after_bridge"></a>`transfer_after_bridge` | 指定桥接完成后要执行的拨号计划转接目的地（`extension [dialplan [context]]`）。 |
| <a id="var-transfer_after_early_bridge"></a>`transfer_after_early_bridge` | 指定 B 腿应答前早期媒体桥接终止时要转入的拨号计划目的地。对应 `SWITCH_TRANSFER_AFTER_EARLY_BRIDGE_VARIABLE`。 |
| <a id="var-call_timeout"></a>`call_timeout` | 使用 `bridge` 应用时等待 B 腿应答的最长秒数。设置在 A 腿上，控制该通道的所有桥接。收到早期媒体后不再生效，除非还设置了 `ignore_early_media=true`。默认：60。 |
| <a id="var-park_timeout"></a>`park_timeout` | 在驻留通道上设置后，经过指定秒数即断开呼叫。可使用整数或 `seconds:HANGUP_CAUSE_NAME` 格式；不设置则呼叫保持驻留，直到明确转接。示例：`park_timeout=30:MEDIA_TIMEOUT`。 |
| <a id="var-fail_on_single_reject"></a>`fail_on_single_reject` | 适用于桥接拨号字符串使用 `,`（AND）运算符的情况。为 `true` 时，任一目的地拒绝即终止整个桥接尝试。也可设为特定原因（`USER_BUSY`）以仅在该原因下失败，或使用否定原因（`!NORMAL_CLEARING`）匹配其他所有原因。支持自定义分隔符列表 `^^:CAUSE1:CAUSE2`。默认：`false`。 |
| <a id="var-failure_causes"></a>`failure_causes` | 以逗号分隔的 Q.850 原因名称列表。桥接以其中某个原因返回时，视通道为失败并调用 `transfer_on_fail`。作用与 `continue_on_fail` 相反。定义于 `switch_channel.c`。 |
| <a id="var-transfer_on_fail"></a>`transfer_on_fail` | 桥接失败时执行的拨号计划转接目的地，与 `failure_causes` 配合使用。格式：`extension [dialplan [context]]`。定义于 `switch_channel.c`。 |
| <a id="var-bridge_early_media"></a>`bridge_early_media` | 为 `true` 时，缓存 B 腿早期媒体阶段收到的实时音频，并作为回铃音播放给 A 腿。相较默认值 `false`，会消耗更多资源。适用于 Loopback 通道或多目的地呼出，需要准确转发网络生成提示音的场景。 |
| <a id="var-ignore_early_media"></a>`ignore_early_media` | 控制早期媒体（携带 SDP 的 SIP 183）是否导致桥接立即视为“接通”。`true` 忽略早期媒体，持续振铃直到 B 腿应答。`ring_ready` 与 `true` 类似，但收到首个 183 时还会向 A 腿发送 SIP 180。默认：`false`。 |
| <a id="var-ringback"></a>`ringback` | 等待 B 腿应答时（早期媒体阶段）播放给 A 腿的音频。支持音频文件的完整路径或 TGML 音调字符串（如 `%(2000,4000,440,480)`）。除非设置 `ignore_early_media`，否则仅在 B 腿没有提供早期媒体时生效。 |
| <a id="var-transfer_ringback"></a>`transfer_ringback` | 已应答通道在转接期间播放给 A 腿的音频；格式与 `ringback` 相同。 |
| <a id="var-transfer_fallback_extension"></a>`transfer_fallback_extension` | 转接失败时要转入的拨号计划分机。必须在执行转接前设置。 |
| <a id="var-hold_music"></a>`hold_music` | 通道被保持时播放的音频流。支持本地流引用（如 `local_stream://moh`）或音频文件完整路径。 |
| <a id="var-temp_hold_music"></a>`temp_hold_music` | 仅对一次保持操作覆盖 `hold_music`；保持结束后自动清除。对应 `switch_types.h` 中的 `SWITCH_TEMP_HOLD_MUSIC_VARIABLE`。 |
| <a id="var-instant_ringback"></a>`instant_ringback` | 为 `true` 时，不等待 B 腿振铃指示，立即生成 `ringback` 指定的回铃音。默认：`false`。 |
| <a id="var-max_forwards"></a>`max_forwards` | 设置该通道出站 SIP 请求的 Max-Forwards 头字段值。对应 `SWITCH_MAX_FORWARDS_VARIABLE`。 |
| <a id="var-max_session_transfers"></a>`max_session_transfers` | 通道允许转接的最大次数；超过后将拒绝后续转接。对应 `switch_types.h` 中的 `SWITCH_MAX_SESSION_TRANSFERS_VARIABLE`。 |
| <a id="var-export_vars"></a>`export_vars` | 逗号分隔的变量名列表，自动导出到桥接创建的任一 B 腿，相当于对每个变量调用 `export`。对应 `SWITCH_EXPORT_VARS_VARIABLE`。 |
| <a id="var-bridge_export_vars"></a>`bridge_export_vars` | 与 `export_vars` 相似，但变量仅在当前桥接期间导出到 B 腿，不永久保留。对应 `SWITCH_BRIDGE_EXPORT_VARS_VARIABLE`。 |
| <a id="var-send_silence_when_idle"></a>`send_silence_when_idle` | 整数。设为负值（通常 `-1`）时，如果没有音频可发送，FreeSWITCH 会向通道发送舒适噪声静音包，避免需要持续媒体流的设备发生 RTP 超时。由 `switch_ivr.c`、`switch_rtp.c` 读取。对应 `SWITCH_SEND_SILENCE_WHEN_IDLE_VARIABLE`。 |
| <a id="var-playback_terminators"></a>`playback_terminators` | 触发立即停止音频文件播放的 DTMF 数字串，例如 `1234567890*#`。设为 `none` 禁用按键中止。适用于 `playback`、`read`、`play_and_get_digits` 等应用。对应 `SWITCH_PLAYBACK_TERMINATORS_VARIABLE`。 |
| <a id="var-ignore_display_updates"></a>`ignore_display_updates` | 为 `true` 时，静默忽略仅修改显示名称的入站 SIP UPDATE 或 re-INVITE，不转发给桥接对端。对应 `SWITCH_IGNORE_DISPLAY_UPDATES_VARIABLE`。 |
| <a id="var-enable_heartbeat_events"></a>`enable_heartbeat_events` | 整数秒数。设置后，FreeSWITCH 按指定间隔在通道上触发 `SESSION_HEARTBEAT` 事件，适用于长通话监控。对应 `SWITCH_ENABLE_HEARTBEAT_EVENTS_VARIABLE`。 |

### 路由与恢复控制 {#routing-and-recovery-controls}

这些变量控制拨号计划转接/重定向行为及呼叫恢复。

| 变量 | 用途 |
|---|---|
| <a id="var-force_transfer_context"></a>`force_transfer_context` | 当 `transfer` 参数未指定上下文时，强制使用此拨号计划上下文。 |
| <a id="var-force_transfer_dialplan"></a>`force_transfer_dialplan` | 当 `transfer` 参数未指定拨号计划引擎时，强制使用此引擎。 |
| <a id="var-inbound_dialplan"></a>`inbound_dialplan` | 覆盖端点入站呼叫所使用的拨号计划引擎。 |
| <a id="var-group_context"></a>`group_context` | 由 `group` 拨号器创建的通道使用的拨号计划上下文。 |
| <a id="var-inline_destination"></a>`inline_destination` | 重定向或已挂机呼叫腿执行内联拨号计划时使用的目的地。 |
| <a id="var-disable_q850_reason"></a>`disable_q850_reason` | 为 `true` 时，在 SIP 挂机信令中禁止携带 Q.850 `Reason` 头。 |
| <a id="var-ignore_completed_elsewhere"></a>`ignore_completed_elsewhere` | 为 `true` 时，忽略 CANCEL 中的 SIP“已在其他位置接听”指示，不将呼叫标记为其他位置已应答。 |
| <a id="var-enum_nameserver"></a>`enum_nameserver` | `mod_enum` 执行 ENUM 查询所使用的 DNS 名称服务器。 |
| <a id="var-recovery_profile_name"></a>`recovery_profile_name` | 覆盖用于呼叫恢复、已存储的 SIP 配置实例名称。 |
| <a id="var-secondary_recovery_module"></a>`secondary_recovery_module` | 恢复呼叫时查询的备用端点模块名称。 |

## 桥接与转接 {#bridge-and-transfer}

桥接或转接处于活动状态或刚完成时，这些变量由核心设置。大多数在运行时只读，少数也允许运维人员设置以影响行为。

| 变量 | 用途 |
|---|---|
| <a id="var-bridge_channel"></a>`bridge_channel` | 建立桥接时由核心在两条腿上设置；值为对端通道名称（如 `sofia/internal/1001@10.0.0.1`）。只读；在 `switch_ivr_bridge.c` 中设置。对应 `SWITCH_BRIDGE_CHANNEL_VARIABLE`。 |
| <a id="var-bridge_uuid"></a>`bridge_uuid` | 建立桥接时由核心在两条腿上设置，包含对端通道 UUID。桥接结束时清除。只读。对应 `SWITCH_BRIDGE_UUID_VARIABLE`。 |
| <a id="var-bridge_to"></a>`bridge_to` | 桥接完成后设置为最近一次被桥接的 B 腿通道名称。只读；对应 `switch_types.h` 中的 `SWITCH_BRIDGE_VARIABLE`（`bridge_to`）。 |
| <a id="var-last_bridge_to"></a>`last_bridge_to` | 新桥接取代旧桥接时，保存之前被桥接 B 腿的通道名称。适用于查看多次顺序桥接的历史。只读；对应 `SWITCH_LAST_BRIDGE_VARIABLE`。 |
| <a id="var-signal_bridge_to"></a>`signal_bridge_to` | 仅信令桥接使用的对端通道 UUID（供 `uuid_bridge` 使用）。两条腿互通信令，但媒体独立处理；可在调用 `signal_bridge` 前由运维人员设置。对应 `SWITCH_SIGNAL_BRIDGE_VARIABLE`。 |
| <a id="var-signal_bond"></a>`signal_bond` | 建立信令桥接后，该通道被设置为信令绑定对端的 UUID。只读；由 `switch_ivr_bridge.c` 设置。对应 `SWITCH_SIGNAL_BOND_VARIABLE`。 |
| <a id="var-originate_signal_bond"></a>`originate_signal_bond` | 呼出完成后立即在 A 腿设置为新建 B 腿的 UUID。不同于 `signal_bond`，这里记录呼出关系，而非后续建立的信令桥接。只读。对应 `SWITCH_ORIGINATE_SIGNAL_BOND_VARIABLE`。 |
| <a id="var-originator"></a>`originator` | 发起本呼叫腿的源通道 UUID。呼出引擎在 B 腿设置。只读；对应 `SWITCH_ORIGINATOR_VARIABLE`。 |
| <a id="var-originator_codec"></a>`originator_codec` | 发起呼出时 A 腿的编解码器字符串。核心（`switch_core_session.c`）在 B 腿设置，以便其提供兼容的编解码器列表。只读；对应 `SWITCH_ORIGINATOR_CODEC_VARIABLE`。 |
| <a id="var-originator_video_codec"></a>`originator_video_codec` | 呼出时 A 腿的视频编解码器字符串，与 `originator_codec` 一起在 B 腿设置。只读；对应 `SWITCH_ORIGINATOR_VIDEO_CODEC_VARIABLE`。 |
| <a id="var-exec_after_bridge_app"></a>`exec_after_bridge_app` | 桥接返回后立即在该通道执行的拨号计划应用名称。应用先于拨号计划恢复执行。对应 `SWITCH_EXEC_AFTER_BRIDGE_APP_VARIABLE`。 |
| <a id="var-exec_after_bridge_arg"></a>`exec_after_bridge_arg` | 传递给 `exec_after_bridge_app` 指定应用的参数字符串。对应 `SWITCH_EXEC_AFTER_BRIDGE_ARG_VARIABLE`。 |
| <a id="var-att_xfer_result"></a>`att_xfer_result` | `att_xfer`（咨询转接）执行结束后设置为 `success` 或 `failure`。只读；由 `mod_dptools.c` 设置。对应 `SWITCH_ATT_XFER_RESULT_VARIABLE`。 |
| <a id="var-transfer_history"></a>`transfer_history` | 多值变量。每次转接追加一条 `epoch:uuid:type:destination` 格式的记录，CDR 模块据此还原转接链。只读；由 `switch_ivr.c` 和 `mod_sofia` 设置。对应 `SWITCH_TRANSFER_HISTORY_VARIABLE`。 |
| <a id="var-transfer_source"></a>`transfer_source` | 标识通道最近一次转接的来源，格式与 `transfer_history` 条目相同。只读；与 `transfer_history` 一起设置。对应 `SWITCH_TRANSFER_SOURCE_VARIABLE`。 |
| <a id="var-holding_uuid"></a>`holding_uuid` | 与当前通道关联、正处于保持状态的通道 UUID。由 `mod_sofia` 在咨询转接场景设置；呼出引擎在桥接回来时读取并清除。对应 `SWITCH_HOLDING_UUID_VARIABLE`。 |
| <a id="var-soft_holding_uuid"></a>`soft_holding_uuid` | 三方通话等场景中处于“软保持”的通道 UUID。三方通话结束、保持方重新桥接回来时清除。对应 `SWITCH_SOFT_HOLDING_UUID_VARIABLE`。 |
| <a id="var-endpoint_disposition"></a>`endpoint_disposition` | 描述 `mod_sofia` 和核心状态机设置的 SIP 协商结果。常见值有 `RECEIVED`、`EARLY MEDIA`、`ANSWER`、`PROXY MEDIA`、`DELAYED NEGOTIATION`、`CODEC NEGOTIATION ERROR`、`NO CODECS`、`REDIRECT_ERROR`、`ATTENDED_TRANSFER`。只读。对应 `SWITCH_ENDPOINT_DISPOSITION_VARIABLE`。 |
| <a id="var-channel_name"></a>`channel_name` | 完整通道名称字符串（如 `sofia/internal/1001@example.com`），由核心创建通道时设置。只读；对应 `SWITCH_CHANNEL_NAME_VARIABLE`。 |
| <a id="var-audio_spool_path"></a>`audio_spool_path` | 音频文件写入最终位置之前的暂存目录。设置后，核心先将音频写到此路径，再移动到最终位置。对应 `SWITCH_AUDIO_SPOOL_PATH_VARIABLE`。 |

### 桥接行为与执行前操作 {#bridge-behavior-and-pre-execution}

这些变量用于调整 `bridge`、`uuid_bridge`、咨询转接/盲转以及 `intercept` 应用的行为。

| 变量 | 用途 |
|---|---|
| <a id="var-bridge_answer_timeout"></a>`bridge_answer_timeout` | 桥接期间等待 A 腿应答的秒数，超时则退出。单位为整数秒。 |
| <a id="var-bridge_terminate_key"></a>`bridge_terminate_key` | 收到后终止桥接的 DTMF 按键；单字符字符串。 |
| <a id="var-bridge_filter_dtmf"></a>`bridge_filter_dtmf` | 为 `true` 时，在桥接两端过滤 DTMF，不向对端透传。 |
| <a id="var-bridge_generate_comfort_noise"></a>`bridge_generate_comfort_noise` | 桥接时向远端呼叫腿生成舒适噪声。`true` 使用 1400 级别，也可指定整数级别（小于 `-1` 的值表示禁用）。 |
| <a id="var-continue_on_answer_timeout"></a>`continue_on_answer_timeout` | 为 `true` 时，即使达到应答超时，桥接仍继续而不判为失败。 |
| <a id="var-answer_delay"></a>`answer_delay` | 通道应答后立即休眠的毫秒数。整数毫秒；代理/文本模式下忽略。 |
| <a id="var-answer_flags"></a>`answer_flags` | 未传参数调用 `answer` 应用时使用的默认标志。通过子串匹配 `is_conference`、`decode_video` 和 `debug_video` 设置对应通道标志。 |
| <a id="var-bridge_pre_execute_app"></a>`bridge_pre_execute_app` | 在桥接循环开始前于 A 腿执行的拨号计划应用。 |
| <a id="var-bridge_pre_execute_data"></a>`bridge_pre_execute_data` | 传递给 `bridge_pre_execute_app` 的参数数据。 |
| <a id="var-bridge_pre_execute_aleg_app"></a>`bridge_pre_execute_aleg_app` | 多线程桥接开始前在主叫（A）腿执行的应用。 |
| <a id="var-bridge_pre_execute_aleg_data"></a>`bridge_pre_execute_aleg_data` | 传递给 `bridge_pre_execute_aleg_app` 的参数数据。 |
| <a id="var-bridge_pre_execute_bleg_app"></a>`bridge_pre_execute_bleg_app` | 多线程桥接开始前在被叫（B）腿执行的应用。 |
| <a id="var-bridge_pre_execute_bleg_data"></a>`bridge_pre_execute_bleg_data` | 传递给 `bridge_pre_execute_bleg_app` 的参数数据。 |
| <a id="var-campon"></a>`campon` | 为 `true` 时，在 `bridge` 中启用驻留等待重试（camp-on）行为。 |
| <a id="var-attended_transfer_no_copy"></a>`attended_transfer_no_copy` | 咨询转接时不在呼叫腿之间复制的变量名列表，以逗号分隔。 |
| <a id="var-blind_transfer_uuid"></a>`blind_transfer_uuid` | 执行盲转时应挂机或转接的呼叫腿 UUID。 |
| <a id="var-confirm_blind_transfer"></a>`confirm_blind_transfer` | 为 `true` 时，盲转需要执行确认处理。 |
| <a id="var-deny_refer_requests"></a>`deny_refer_requests` | 在已桥接呼叫腿上为 `true` 时，拒绝入站 SIP REFER（转接）请求。 |
| <a id="var-hold_hangup_xfer_exten"></a>`hold_hangup_xfer_exten` | 保持中的呼叫腿桥接结束后，将另一腿转接至该分机，而非直接挂机。 |
| <a id="var-xfer_uuids"></a>`xfer_uuids` | 提供 `att_xfer` 操作所需的两条腿 UUID。 |
| <a id="var-intercept_pre_bond"></a>`intercept_pre_bond` | 为 `true` 时，允许 `intercept` 抢接尚未完成绑定的呼叫腿。 |
| <a id="var-intercept_unanswered_only"></a>`intercept_unanswered_only` | 为 `true` 时，`intercept` 仅允许抢接未应答呼叫腿。 |
| <a id="var-intercept_unbridged_only"></a>`intercept_unbridged_only` | 为 `true` 时，`intercept` 仅允许抢接未桥接呼叫腿。 |
| <a id="var-uuid_bridge_continue_on_cancel"></a>`uuid_bridge_continue_on_cancel` | 为 `true` 时，在某腿取消 `uuid_bridge` 时驻留剩余呼叫腿，而不是挂断。 |

### SIP 变量约定 {#sip-variable-conventions}

`mod_sofia` 使用 `sip_h_` 前缀将所有入站 SIP 头暴露为通道变量。对标准头而言，例如 `sip_h_Subject`、`sip_h_P-Asserted-Identity` 等。对于出站呼叫，设置以 `sip_h_` 开头的通道变量，会使 `mod_sofia` 在出站 INVITE 或其他 SIP 消息中注入对应头（去掉前缀即为头名称）。自定义扩展头遵循同样约定：`sip_h_X-My-Header=value` 会在 INVITE 中生成 `X-My-Header: value`。

除了原始的 `sip_h_` 映射，`mod_sofia` 还会在呼叫到达时将一些常用头解析为专用变量：

- `sip_from_user`, `sip_from_host`, `sip_from_uri`, `sip_from_display`
- `sip_to_user`, `sip_to_host`, `sip_to_uri`, `sip_req_uri`
- `sip_contact_user`, `sip_contact_host`
- `sip_call_id`, `sip_user_agent`
- `sip_via_host`, `sip_via_port`, `sip_via_rport`, `sip_via_protocol`
- `sip_network_ip`, `sip_received_ip`

这些解析后的变量只是方便使用的别名；如有需要，仍可通过 `sip_h_` 前缀读取原始头。

### RTP 与媒体统计 {#rtp-and-media-statistics}

FreeSWITCH 在呼叫进行期间和结束后，向一组 `rtp_*` 通道变量填充各媒体流的统计数据。这些只读变量用于诊断，不能通过设置它们来改变行为。例如：

- `rtp_audio_in_raw_bytes`、`rtp_audio_in_media_bytes`、`rtp_audio_in_packet_count`、`rtp_audio_in_media_packet_count`：入站音频流计数器。
- `rtp_audio_out_raw_bytes`、`rtp_audio_out_media_bytes`、`rtp_audio_out_packet_count`：出站音频流计数器。
- `rtp_audio_in_skip_packet_count`、`rtp_audio_in_jitter_packet_count`、`rtp_audio_in_dtmf_packet_count`：入站媒体流的质量指标。
- `rtp_use_codec_string`：实际选用且正在供 RTP 使用的编解码器字符串，而非此前 Offer 中提供的编解码器。

这些变量由 `switch_rtp.c` 和 `switch_core_media.c` 写入，可用于 CDR 模板，也可通过 `api_hangup_hook` 或 `api_reporting_hook` 生成呼叫结束后的报告。

## DTMF {#dtmf}

这些变量控制通道上的 DTMF 处理。

| 变量 | 用途 |
|---|---|
| <a id="var-dtmf_type"></a>`dtmf_type` | 设置出站呼叫腿的 DTMF 信令方式。取值：`rfc2833`（带内 RTP telephone-event）、`info`（SIP INFO 消息）、`none`（不发送 DTMF）。未设置时使用 SDP 协商结果。FreeSWITCH 在 `switch_core_media.c` 中读写此变量。若要检测音频带内 DTMF，还必须在拨号计划中调用 `start_dtmf`。 |

| <a id="var-sensitive_dtmf"></a>`sensitive_dtmf` | 为 `true` 时，不在应用日志中记录 DTMF 事件；适用于处理 PIN 输入的通道。对应 `SWITCH_SENSITIVE_DTMF_VARIABLE`。 |
