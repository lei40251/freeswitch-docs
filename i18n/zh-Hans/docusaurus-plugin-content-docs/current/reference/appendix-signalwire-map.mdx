FreeSWITCH 也作为托管平台运行。由 FreeSWITCH 团队创立的 SignalWire，在一组 API 后面运行着同一套引擎，包括 SWML（一种 JSON 或 YAML 格式的呼叫控制标记语言）、REST API、实时 WebSocket SDK 和无代码流程构建器。本附录将本手册记录的每项功能映射至相应的托管能力，便于你逐项权衡自托管与平台托管，也可以同时运行两者。

你可以通过以下三种方式使用本映射表：

1. **扩展现有部署。** 保留自己的 FreeSWITCH 服务器，同时增加托管能力，例如 SIP 中继、SMS，或可以通过某条拨号计划 Extension 访问的 AI 智能体。参见[第 30 章](../integration/signalwire.mdx)及[为 FreeSWITCH 添加 AI 的指南](https://signalwire.com/docs/platform/freeswitch/add-ai-to-freeswitch?utm_source=freeswitch-docs&utm_medium=appendix&utm_campaign=same-engine&utm_content=capability-map)。
2. **让下一个项目托管运行。** 每一行的 SignalWire 列都对应你已熟悉章节的 API 形式。
3. **迁移现有业务负载。** 由于底层引擎相同，相关概念几乎可以一一对应地迁移。
