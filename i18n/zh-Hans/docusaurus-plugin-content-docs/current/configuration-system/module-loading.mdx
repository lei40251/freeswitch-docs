# 第 5 章：模块加载与管理 {#chapter-5-module-loading-and-management}

FreeSWITCH 的功能由模块提供。本章介绍启动时如何选择加载模块、专用的提前和延后加载文件，以及通过控制台加载、卸载和重新加载模块的方法。

## 构建时与运行时的模块选择 {#build-time-vs-runtime-module-selection}

FreeSWITCH 将模块可用性分成编译和运行时加载两个独立阶段。

**构建时**：`build/modules.conf.in`（或由其创建的本地 `modules.conf`）控制构建系统编译哪些模块。未以 `#` 开头的行会使对应的 `.so` 共享库被构建并安装，已注释的行则不构建对应共享库。

**运行时**：`autoload_configs/modules.conf.xml` 控制 FreeSWITCH 启动时实际加载哪些已安装模块。`<load>` 元素指示 FreeSWITCH 从模块目录打开指定共享库。

编译安装是加载的严格前提。为未构建的模块启用 `<load>` 会在启动日志中产生加载错误；FreeSWITCH 仍继续启动，但该模块不可用。反过来，模块已编译但在 `modules.conf.xml` 中保持注释没有问题，此时 `.so` 存在于磁盘上但不被加载。

常见流程是编辑 `build/modules.conf.in`、重新编译（`make && make install`），然后在 `modules.conf.xml` 中启用对应 `<load>` 行。

`build/modules.conf.most` 是范围更广的替代构建清单，启用多数可选模块。默认构建不使用它；需要一次构建更完整的模块集合时，可复制或引用该文件。

## modules.conf.xml {#modulesconfxml}

`modules.conf.xml` 列出启动时加载的模块。文件包含单个 `<modules>` 块，每个模块对应一个 `<load>` 元素：

```xml
<configuration name="modules.conf" description="Modules">
  <modules>
    <load module="mod_console"/>
    <load module="mod_sofia"/>
    <load module="mod_dptools"/>
  </modules>
</configuration>
```

添加或取消注释对应的 `<load>` 行即可启用模块，注释或删除该行即可禁用。更改在重启后生效，也可通过下文的运行时命令立即应用。模块必须已安装才能加载；为未构建的模块启用 `<load>` 会在日志中产生加载错误。

## 提前与延后加载 {#early-and-late-loading}

两个配套文件控制需要在主模块集合之前或之后加载的模块。FreeSWITCH 按以下顺序处理：

1. `pre_load_modules.conf.xml`
2. `modules.conf.xml`
3. `post_load_modules.conf.xml`

各文件均使用相同的 `<load module="..."/>` 语法。

**`pre_load_modules.conf.xml`**：随附默认配置加载一个模块：

```xml
<configuration name="pre_load_modules.conf" description="Modules">
  <modules>
    <!-- Databases -->
    <!-- <load module="mod_mariadb"/> -->
    <load module="mod_pgsql"/>
  </modules>
</configuration>
```

`mod_pgsql` 提供 PostgreSQL 数据库后端。其他模块（包括核心子系统）可能在自身初始化期间打开数据库连接，因此数据库驱动必须在主加载序列开始前可用。`mod_mariadb` 是已注释的 MariaDB 或 MySQL 后端替代项；可替换 `mod_pgsql`，也可同时启用以支持两种后端。

当 FreeSWITCH 从 HTTP 服务器获取配置、用户目录和拨号计划文档时，应在此启用 `mod_xml_curl`：XML 接口必须在消费这些文档的模块初始化前注册，因此需要提前加载。

**`post_load_modules.conf.xml`**：默认为空，用于依赖完整模块集合已完成初始化的模块。目前没有随附模块需要它。

| 文件 | 默认内容 | 典型用途 |
| --- | --- | --- |
| `pre_load_modules.conf.xml` | 启用 `mod_pgsql` | 数据库后端、XML 提供器 |
| `modules.conf.xml` | 完整的可用 PBX 模块集合 | 所有标准模块 |
| `post_load_modules.conf.xml` | 空 | 依赖延后初始化的模块 |

## 模块类别 {#module-categories}

模块类别决定其提供的接口类型及读取的配置文件。类别仅用于组织；单个模块可注册多种接口，例如 `mod_enum` 同时提供拨号计划接口、应用和 API 命令。

| 类别 | 提供的接口 |
| --- | --- |
| `endpoints` | 呼叫信令协议 |
| `applications` | 拨号计划应用与 API 命令 |
| `dialplans` | 拨号计划解释器 |
| `codecs` | 音视频编解码器 |
| `formats` | 文件和流的读写器 |
| `event_handlers` | 外部事件接口与 CDR 后端 |
| `loggers` | 日志目标 |
| `languages` | 内嵌脚本运行时 |
| `say` | 各语言的短语呈现 |
| `asr_tts` | 语音识别与合成 |
| `timers` | 计时源 |
| `databases` | 外部数据库后端 |
| `directories` | 外部用户目录后端 |
| `xml_int` | 动态 XML 提供器 |

## 运行时管理模块 {#managing-modules-at-runtime}

可以通过 `fs_cli` 加载、卸载和重新加载模块，无需重启。

| 命令 | 效果 |
| --- | --- |
| `load mod_name` | 立即加载模块 |
| `unload mod_name` | 立即卸载模块 |
| `reload mod_name` | 卸载后重新加载模块，并重新读取配置 |
| `reloadxml` | 重新解析 XML 文档，不改变已加载模块 |
| `show modules` | 列出当前已加载的模块 |

`reloadxml` 刷新配置文档，但不会加载或卸载模块。如果模块缓存自身配置，而你修改了该配置，应使用 `reload mod_name`。各模块是否需要重新加载，详见对应章节。
